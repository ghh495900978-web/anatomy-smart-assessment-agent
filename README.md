# 体态解码师 × 智评学径 — 融合版部署与运行说明

> 面向「健康服务与管理」专业的人体解剖学智能训练与测评系统
> 参赛作品 · 首届教学智能体大赛 · **申报组别：学习赋能智能体**

## 零、设计主轴：一个六维坐标系，而不是两个并列模块

本版的核心重构是**真融合**。此前「体态解码」与「系统测评」是两个并列模块——
两套能力维度、两份 localStorage 档案、中间只靠一个硬编码跳转按钮连接。

现在两者共用**同一套六维能力模型（L1—L6）**，数据双向流动：

```
      运动系统深学（66 题四层）──┐
                                  ├──► 统一六维能力档案 ──► 双向推荐
      体态实训（五维解码）───────┘        （一份档案）
```

| 维度 | 名称 | 层级 | 主要由谁产出 |
|------|------|------|--------------|
| L1 | 结构定位 | 学科基础 | 测评（A 概念 / C 识图）+ 实训 |
| L2 | 毗邻关系 | 学科基础 | 测评（B 毗邻） |
| L3 | 功能机制 | 学科基础 | 测评（D 功能）+ 实训 |
| L4 | 异常识别 | **专业特色** | 体态实训 + 情境判断题 |
| L5 | 风险沟通 | **专业特色** | 体态实训（风险分级 / 红旗转介） |
| L6 | 管理干预 | **专业特色** | 体态实训（非医疗干预方案） |

**L1—L3 是医学生也要考的学科基础，L4—L6 是健康服务与管理专业独有的能力。**
这一刀解决了"融合"问题：测评负责打地基，实训负责出能力，两者往同一张雷达图上打点。

```
anatomy-agent-v2/
```

**导航为递进式，而非并列：**

```

                   ↑ 主战场                                    ↑ 覆盖面
```

## 零之二、为什么运动系统是主战场

体态解码师本质上就是**运动系统的应用**，那么运动系统的知识底座就必须做厚。
初版 9 个单元各 8—10 题平均用力，导致"应用层很重、知识层很薄"，融合是空对空的。

现在运动系统扩到 **66 题**，按四层组织，与五个体态实训区域一一对齐：

| 层级 | 内容 | 主要能力维度 |
|---|---|---|
| 骨学 · 形态与标志 | 骨的构造、椎骨特征、胸骨角、肩胛骨与髋骨标志 | L1 L2 |
| 关节学 · 运动与稳定 | 椎间盘、脊柱韧带、肩肘髋膝踝、骨盆分界 | L1 L3 |
| 肌学 · 动力与失衡 | 起止点、作用、神经支配、各群肌功能 | L1 L3 L4 |
| 体态生物力学 · 力线与代偿 | 重力线、上下交叉综合征、代偿步态、核心稳定 | L4 L5 |

其余 9 个单元保留为**拓展学练**，保证课程覆盖面与期末复习可用性，但不再占据主导航的同等权重。

**核心特性（已通过 smoke test 31 项断言验证）**
- 🦴 **运动系统 66 题四层深学**：支持按骨学 / 关节学 / 肌学 / 体态生物力学筛选题目
- 🎯 **学情诊断页**：六维雷达 + 能力条 + 成长曲线（基础线 / 专业线双线）+ 数据驱动推荐
- 🔗 **双向数据驱动推荐**：测评薄弱 → 自动匹配体态实训区域；能力短板 → 反推应补单元（不再硬编码）
- 🧾 **全部题目情境化**：每题带「健康服务场景」、知识层级与能力维度标签
- 📦 **统一能力档案**：两份老 localStorage 档案首次打开即自动迁移合并为一份（`hsm_anatomy_competency_v1`）
- 🧍 体态解码工作台：5 大体态分析区 + 课程图谱 + 五维解码报告
- 教学法设计：脚手架递减（示范→补全→独立）、学习证据自评（不由系统代判）、红旗转介识别（职业边界）
- 10 个单元题库：运动 / 消化 / 呼吸 / 泌尿 / 生殖 / 内分泌 / 循环 / 神经 / 感觉器 / 绪论（86 题带解析 + 选项随机乱序）
- 9 幅原创 SVG 识图题配图 + 掌握度建模（指数平滑知识追踪）+ 自适应出题
- 61 节点知识图谱（KG），含前置依赖关系
- ECharts 可视化：六维雷达 / 成长曲线 / 柱状图 / 饼图 / 知识图谱 graph
- 大模型接入框架（兼容 OpenAI 协议：智谱 GLM-4-Flash / 通义千问 / Kimi / 自定义）
- 师生双端设计（教师端 PIN: `anatomy2026`）
- AI 智能伴学（主面板 + 浮窗入口）+ Web Speech 语音输入

## 二、本地预览（任选一种）

### 方式 A：直接打开 index.html

最简单，但不推荐（部分浏览器对 `fetch` 与跨域有限制）。

```bash

```

```bash
cd anatomy-agent-v2
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

### 方式 C：用 Node 起静态服务

```bash
cd anatomy-agent-v2
npx serve -p 8080
# 或
npx http-server -p 8080
```

## 三、部署到 Netlify（最简单，原站点沿用方案）

### 3.1 拖拽部署（无需 GitHub）

1. 打开 https://app.netlify.com/drop
2. 把整个 `anatomy-agent-v2/` 文件夹拖进去
3. Netlify 会自动分配 `xxx.netlify.app` 域名
4. 可在 Netlify 控制台 → Domain settings → Custom domain 绑定自有域名

### 3.2 GitHub 部署（推荐，可持续更新）

```bash
cd anatomy-agent-v2
git init
git add .
git commit -m "feat: 人体解剖学智评学径智能体 v2"
# 在 GitHub 新建空仓库，按提示 push

# 然后在 Netlify 控制台：
# Add new site → Import from Git → 选择仓库
# Build command: 留空（纯静态）
# Publish directory: .
# 点击 Deploy
```

### 3.3 升级原站点

把 `index.html` / `styles.css` / `app.js` 三个文件覆盖到原 `posture-decoder-anatomy-agent` 仓库，
提交即可触发 Netlify 自动部署。

## 七、故障排查

### 7.1 页面打开后图表不显示

检查浏览器控制台 Network 面板，确认 ECharts CDN 是否加载成功（默认从 jsDelivr 引入）。
如果被墙，可改为 unpkg：`https://unpkg.com/echarts@5.4.3/dist/echarts.min.js`

### 7.2 AI 伴学一直走本地模拟

- 浏览器控制台检查是否报错
- 教师端确认 API Key 已保存（保存后会写入 localStorage）
- 国内网络访问 OpenAI 需要代理，建议先用智谱 / 通义千问 / Kimi

### 7.3 数据没保存

确认浏览器未开启「无痕模式」（localStorage 在无痕模式下不持久化）。
